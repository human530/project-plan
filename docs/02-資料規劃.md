# 02・資料規劃（Data Plan）

> 本文件是「RA 手部 X 光 AI 自動損傷評分」專題的資料與法遵總藍圖：用最少資源（免費 Colab + Drive）安全、合法、可重現地取得並處理資料，並把「資料拿不到」這個最大風險先拆解、先佈局。

- 適用對象：高中參賽學生與指導老師（含協助申請的家長 / 學校單位）
- 製表：2026-06　|　目標送件：2027 年 10–11 月（TISF）
- 一句話結論：**主資料集（RA2 DREAM）申請要趁早、要有備援；所有資料一律走「病人層級切分 + 去識別化檢核」，寧可資料少也不要資料外洩。**

## 1. 主資料集：RA2 DREAM Challenge（syn20545111）

### 1.1 它到底是什麼（已查證）

| 項目 | 內容 |
|---|---|
| 來源 | DREAM Challenges × Sage Bionetworks，資料來自兩個既有臨床試驗（含 TEAR trial） |
| 規模 | **674 套**影像，來自 **562 位病人**；切分為訓練 367 套 / 排行榜 119 套 / 最終評估 188 套 |
| 一套是什麼 | 每套含 **4 張影像**：左手腕、右手腕、左足、右足，皆為後前位（PA）投照 |
| 影像格式 | 放射影像 + 對應的專家 SvH 分數表 |
| 平台 | Synapse（synapse.org），ID：`syn20545111` |

> 註：原計畫寫「手 / 腕 / 足 X 光」正確；但要提醒學生**本題只用手 + 腕**，足部影像對「手部評分」沒有直接幫助（見 §8 盲點）。

### 1.2 SvH 分數欄位結構（已查證，務必看懂）

Sharp–van der Heijde（SvH）是**逐關節**分開評「骨侵蝕（erosion）」與「關節間隙狹窄（JSN）」再加總：

| 部位 | 評分項 | 關節 / 區域數（單側） | 每關節分數範圍 |
|---|---|---|---|
| 手 + 腕 | 骨侵蝕 erosion | 16 區 | 0–5 |
| 手 + 腕 | 間隙狹窄 JSN | 15 區 | 0–4 |
| 足 | 骨侵蝕 erosion | 6 區 | 0–10（雙側計） |
| 足 | 間隙狹窄 JSN | 6 區 | 0–4 |

- **手部（左右合計）理論上限**：erosion 約 160 分、JSN 約 120 分。
- **全身（含足）總分上限：448 分**（這是文獻給的數字，可在報告中引用）。
- DREAM 提供的標註欄位通常是**每個關節一欄**（例如 `LH_MCP1_E`、`LH_PIP2_J` 之類）＋總分欄位。實際欄位命名需以拿到的 Excel/CSV 為準 → **標註「拿到後第一件事就是畫出分數分布直方圖」**。

### 1.3 標註品質（可寫進報告當作「標籤可信度」依據，已查證）

- 原始分數由**專家讀片者**評定；兩位專家在 TEAR trial 的判讀者間變異係數（CoV）：總分 0.74、JSN 0.62、erosion 0.73 → 代表**連專家之間都有不小差異**，這是本題「上限」的天花板，必須在報告誠實討論。
- 主辦方對離群分數做了人工複核修正（JSN 約 1.2%、erosion 約 2.3% 被修），代表標籤整體乾淨但非完美。

### 1.4 申請流程（已查證的 Synapse 機制 + 操作步驟）

Synapse 的受控資料一般需要：**註冊帳號 → 成為 Certified User（認證）→ 同意該資料的 Conditions for Use（可能含 Intended Data Use 聲明 / 資料使用證明 / 甚至 IRB）**，每位使用者需個別同意。

**建議操作步驟（A 軌）：**

- [ ] **2026 年 7 月初**：由指導老師 / 家長註冊 Synapse 帳號（成人帳號較不會卡學生身份問題）。
- [ ] 完成 **Certified User** 認證（線上小測驗，關於資料倫理）。
- [ ] 進入 `syn20545111`，閱讀該專案的 **Conditions for Use / Data Use Statement**，確認是否仍開放索取（賽事 2020 已結束，資料未必持續釋出 → **需進一步確認**）。
- [ ] 填寫 **Intended Data Use 聲明**：寫明「高中科展、非商業、僅研究用途、結果不重新識別個人、不轉散布」。
- [ ] 若頁面無自助下載按鈕 → 到該專案 **Discussion 區或聯絡主辦方 / 通訊作者**禮貌詢問取得方式（附老師署名信更有說服力）。
- [ ] **全程截圖存證**（申請日期、信件往返），TISF 評審可能會問資料來源合法性。

> ⚠️ 誠實標註：**「賽後該資料是否仍對外（尤其對未隸屬研究機構的高中個人）開放下載」目前無法 100% 確認，需以實際申請結果為準。** 因此 B 軌（後援）不是備案，是**必做**。

## 4. DICOM / PNG 前處理管線（具體、可照做）

### 4.1 從 DICOM 到模型輸入（NYCU / RA2 多為 DICOM）

| 步驟 | 做法 | 工具 | 關鍵提醒 |
|---|---|---|---|
| 1 讀檔 | 用 `pydicom` 讀像素陣列與 metadata | pydicom | 注意 `PhotometricInterpretation`：若為 `MONOCHROME1` 需**反相**（值越大越黑） |
| 2 Window/Level | 套用 `WindowCenter`/`WindowWidth`；若無則用百分位（如 1%–99%）裁切後線性映射到 0–255 | numpy | 骨頭細節在窗位調對時才清楚；建議固定一套窗位以利可重現 |
| 3 去識別化 | **移除所有 DICOM 個資 tag**（姓名、ID、日期、機構），並**目視檢查影像四角是否有燒入文字（burned-in text）** | pydicom + 目視 | 見 §7 檢核清單 |
| 4 統一尺寸 | 等比例縮放 + padding 到固定邊長（如 512×512 給定位、224/300 給分類） | OpenCV / PIL | **保持長寬比**，不要硬拉變形（會破壞關節幾何） |
| 5 對比增強 | **CLAHE**（限制對比度自適應直方圖均衡），`clipLimit≈2.0`、`tileGridSize=8×8` | `cv2.createCLAHE` | 對骨皮質 / 關節邊緣很有效；增強後再正規化 |
| 6 正規化 | 縮到 [0,1] 或用 ImageNet 均值/標準差（遷移學習） | torchvision | 灰階複製成 3 通道以套用預訓練權重 |
| 7 存檔 | 統一輸出 **PNG（無損）** 到 Drive，附一張對照表（檔名↔病人↔分數） | — | 不要存 JPG（有損會吃掉骨皮質細節） |

### 4.2 資料增強（只在訓練集做，驗證 / 測試集不做）

- 安全的：小角度旋轉（±10°~15°）、水平翻轉（**見下方左右手注意**）、亮度 / 對比抖動、小幅平移 / 縮放、隨機 erasing。
- 謹慎的：彈性形變（可能扭曲關節間隙語意，幅度要小）。
- **左右手處理建議**：把所有手統一翻成同一側（例如全部翻成「右手樣態」）再訓練，減少左右差異噪音；翻轉當增強時要確保標籤的左右對應一起翻。

## 5. 小樣本 + 類別不平衡的具體做法

樣本只有數百套、且高分（重度損傷）關節極少 → 這是本題核心難點。

**對抗小樣本：**
- [ ] **遷移學習**：凍結預訓練骨幹大部分層，只微調後段 + 回歸頭；資料更少時用更輕模型（MobileNet/EfficientNet-B0）。
- [ ] **K 折交叉驗證（病人層級）**：樣本少時用 5-fold 取代單一固定切分，報告平均±標準差，結果更可信。
- [ ] **逐關節切塊放大樣本量**：一張手有十幾個關節 → 做關節定位後，**每個關節 patch 都是一個樣本**，瞬間把 N 從「幾百張手」變「幾千個關節」。這是本題把資料變多的最強招。
- [ ] 善用增強、適度 dropout / weight decay 防過擬合。

**對抗類別 / 分數不平衡：**
- [ ] 先**畫分數分布直方圖**，確認是否大量集中在 0（無損傷）。
- [ ] 分類版：**加權交叉熵**（少數類權重高）或 focal loss；可搭配少數類過採樣 / 多數類欠採樣。
- [ ] 迴歸版：對偏態分數可考慮**對數或平方根轉換**、或用 ordinal regression；損失可對高分樣本加權。
- [ ] 評估時**不要只看整體 RMSE**：高分樣本少，整體誤差會被一堆 0 稀釋 → 另外報告「僅在有損傷關節上的誤差」與分層誤差。

## 6. 病人層級切分與防資料外洩（最容易犯、最致命的錯）

**核心規則：切分的單位是「病人」，不是「影像」。** 同一病人的左右手、不同時間追蹤片，**必須整批落在同一個 set**。

> RA2 是 674 套來自 562 位病人 → 代表**有人有多套**，若按影像隨機切，同一人會同時出現在訓練與測試，準確率會被嚴重高估。

**正確做法：**
- [ ] 用 `sklearn` 的 `GroupShuffleSplit` 或 `StratifiedGroupKFold`，`groups=病人ID`。
- [ ] 切分順序：**先按病人切 → 再做前處理 / 增強**（絕不能先增強再切，否則同一張的增強版會跨集）。
- [ ] 逐關節模型時，**同一張手的所有關節 patch 也要跟著病人走**，不可拆開。

**防外洩自我檢查清單（資料切好後跑一次）：**
- [ ] 訓練集病人ID ∩ 驗證集病人ID ∩ 測試集病人ID ＝ 空集合（寫個 assert 驗證）。
- [ ] 沒有任何「同一原圖的不同增強版本」跨集。
- [ ] 前處理用到的統計量（如正規化均值）**只由訓練集計算**，再套到驗證 / 測試集。
- [ ] 模型選擇 / 調參只看驗證集；測試集**只在最後跑一次**，不可反覆偷看。

## 7. 資料倫理與去識別化檢核清單（TISF 評審會問）

- [ ] 只使用**去識別化、授權清楚**的資料；保留每個資料集的授權條款 / 同意信截圖。
- [ ] DICOM 移除個資 tag：`PatientName`、`PatientID`、`PatientBirthDate`、檢查日期、機構名、設備序號等。
- [ ] **目視檢查影像燒入文字**（角落常有姓名 / 病歷號 / 日期）→ 有就裁切或塗黑。
- [ ] 內部用代號（如 `P001`）取代真實 ID，對照表**單獨加密保存、不放進公開報告 / GitHub**。
- [ ] GitHub repo **不上傳任何原始醫療影像或個資**（用 `.gitignore` 擋掉 data 資料夾）。
- [ ] 報告中明確**免責聲明**：本作品為研究 / 輔助評分用途，非臨床診斷。
- [ ] 不嘗試重新識別任何個人；不二次散布受控資料。
- [ ] 建立一張**「資料卡（Data Card）」**：來源、規模、授權、取得日期、前處理版本、已知偏誤 → 直接貼進研究日誌。

## 8. 原計畫的資料風險、盲點與改善建議

| # | 盲點 / 風險 | 為什麼是問題 | 改善建議 |
|---|---|---|---|
| 1 | 把「後援資料」當備案而非必做 | 主資料集賽後是否開放給高中個人**無法保證** | B 軌（RSNA）**第一週落地**；NYCU 同步申請，雙保險（§3） |
| 2 | 沒區分手 / 腕 / 足 | 本題是「手部」評分，足部影像對手部分數沒幫助，反而增加處理成本 | 明確只取**手 + 腕** PA 片；足部資料僅在做「全身總分」時才碰 |
| 3 | 低估 SvH 分數嚴重不平衡 | 大多數關節是 0 分，重度極少 → 模型容易全猜 0 還拿到漂亮 RMSE | 先畫分布；分層評估；加權損失；報告「有損傷關節」上的誤差（§5） |
| 4 | 標籤被當成完美真值 | 連兩位專家 CoV 都 0.6–0.7，標籤本身有噪音 | 把「專家判讀者間一致性」當作模型**性能天花板**，誠實寫進報告（§1.3） |
| 5 | 切分外洩風險 | 674 套來自 562 人 → 有人多套，影像級切分會高估 | 一律 patient-level + assert 檢查（§6） |
| 6 | 左右手 / 投照角度差異未處理 | 左右手、不同角度增加噪音，小樣本下傷害大 | 統一翻成同側、固定窗位、必要時排除明顯異常投照（§4） |
| 7 | DICOM 去識別化沒寫具體 | 醫療影像常有燒入個資，是倫理紅線 | 用 §7 檢核清單，逐項勾完才進入訓練 |
| 8 | 資料量可能不足以做「逐關節迴歸」 | 幾百張手做精細迴歸很吃力 | 用**關節 patch 把樣本放大**（§5）；MVP 先做整圖「輕 / 中 / 重」分類保底 |
| 9 | 沒有資料版本控管 | 前處理改了卻忘記，結果無法重現 | 凍結資料版本、記資料卡、前處理程式進 Git（§3、§7） |
