## 0. 給指導老師的 30 秒摘要

- **核心策略不變但收斂目標更務實**：第一層不直接硬學「總分 0–448」這個極難的回歸，而是先做**輕/中/重序數分級**當保底，再疊加「整圖回歸總分」當進階比較。文獻顯示直接回歸全分數範圍（0–270）的一致性會掉到 ICC≈0.31，**分段/分級反而穩**。
- **第二層才是真正貼近臨床、也最可能拿到好成績的主力**：先用 YOLO 類偵測器框出 MCP/PIP/腕關節，裁切後逐關節評分再加總。已發表方法用 YOLOv7 做關節定位可達約 99% 命中，逐關節後在 Sharp<50 區間 ICC≈0.70。
- **骨幹一律選小**：EfficientNet-B0 / MobileNetV3 / ResNet-18 等，因為樣本只有數百套，**大骨幹會過擬合**，且 Colab 記憶體吃不消。
- **所有數字與文獻都標了出處**；查不到精確值的地方明確寫「估計值／需自行量測」，沒有編造。

## 2. 任務形式：回歸 vs 序數回歸 vs 分級（最重要的設計決策）

SvH 總分是**有序的整數分數**（典型手部範圍可達數百分），本質上是「序數(ordinal)」而非單純連續，也非無序類別。三種做法取捨：

| 形式 | 輸出 | 優點 | 缺點 | 建議用在 |
|---|---|---|---|---|
| **直接回歸總分** | 1 個連續值 | 直覺、和 MAE/RMSE 指標一致 | 大範圍 + 長尾分布**極難學**（文獻 ICC 掉到 0.31）；對少數高分樣本不敏感 | 第一層**進階比較**用，不當唯一保底 |
| **序數回歸(ordinal)** | K-1 個累積機率（CORAL/CORN） | 利用「等級有序」；相鄰錯誤懲罰小；rank 一致 | 需把分數**分箱**成有序等級；實作比分類稍複雜 | **第一層分級頭首選** |
| **多類別分類** | 輕/中/重 softmax | 最簡單、類別不平衡好處理 | 忽略「中比重更接近」的順序資訊 | 入門基線、和序數做消融對照 |

**本規劃建議**（請務必照此分層，能大幅降低失敗風險）：

1. **第一層保底**：把總分**分箱**成「輕 / 中 / 重」3 級（分箱門檻用訓練集分位數或臨床建議，並在報告中固定寫死）。用**序數回歸損失(CORN)**訓練 → 穩、好解釋。
2. **第一層進階**：同一骨幹再接一個**回歸頭**直接預測總分，損失用 **Huber/SmoothL1**（對高分離群值比 MSE 穩）。可選 **log1p 轉換**或對分數開根號壓縮長尾。
3. **多任務(可選)**：一個骨幹同時輸出「分級(序數) + 回歸值」，兩個損失加權相加，常比單任務穩。

```python
# 損失示意（PyTorch，僅關鍵設定）
import torch.nn.functional as F

# (A) 回歸頭：Huber 比 MSE 對高分離群值更穩
reg_loss = F.smooth_l1_loss(pred_score, target_score, beta=1.0)

# (B) 序數頭：CORN（用 coral_pytorch 套件）
# pip install coral-pytorch
from coral_pytorch.losses import corn_loss
ord_loss = corn_loss(logits, y_levels, num_classes=3)   # y_levels: 0/1/2 有序

# (C) 多任務：加權相加（lambda 自行調，建議 0.3~1.0）
loss = reg_loss + 0.5 * ord_loss
```

> 評估時：回歸看 **Pearson/Spearman、RMSE、MAE、ICC、patient-weighted RMSE**；分級看 **Accuracy、Macro-F1、混淆矩陣、Quadratic Weighted Kappa(序數專用，強烈建議)**。

## 3. 三層模型架構

> 慣例：輸入皆為灰階手部 X 光，**轉成 3 通道**（複製灰階）以相容 ImageNet 預訓練權重。

### 3.1 第一層 MVP（必達）— 整圖評分／分級

**資料流**

```
手 X 光 (原圖, 灰階)
  → 前處理: resize 512→中心裁切, CLAHE 對比強化, 標準化(ImageNet mean/std)
  → 3 通道
  → 預訓練骨幹 (EfficientNet-B0 / ResNet-18, ImageNet 權重)
      ├─ Global Average Pooling → 特徵向量 (1280 或 512 維)
      ├─ Dropout(0.3~0.5)
      ├─ [頭A] 序數分級頭  → 輕/中/重 (CORN, K-1=2 個 logit)
      └─ [頭B] 回歸頭      → 1 個連續總分 (Huber)
```

| 項目 | 設定 | 理由 |
|---|---|---|
| 輸入尺寸 | 384–512 px | X 光細節（骨緣侵蝕）需較高解析度；但受 Colab 記憶體限制，先 384 |
| 骨幹首選 | **EfficientNet-B0**（約 5.3M 參數） | 參數少、準確/算力比高，小樣本不易過擬合 |
| 骨幹備選 | ResNet-18 / MobileNetV3-Large | 更輕、debug 快，當基線對照 |
| 輸出 | 分級(序數) + 回歸(可選多任務) | 分級保底、回歸進階 |

> 為什麼**不用** EfficientNet-B4/ResNet-50：樣本只有數百張，大骨幹參數量是樣本數的數百倍，**幾乎必然過擬合**，且 batch 開不大、Colab 易 OOM。先小後大，需要時再升級並用消融證明值不值得。

### 3.2 第二層 進階（主力）— 關節偵測 → 逐關節評分 → 加總

**資料流**

```
手 X 光
  → [階段1] 關節偵測器 (YOLOv8-pose 關鍵點 或 YOLOv8 偵測框)
        標的: 雙手 MCP×?, PIP×?, 腕關節 等 ROI
  → 依關鍵點/框裁切出每個關節小圖 (e.g. 96×96 或 128×128)
  → [階段2] 逐關節評分 CNN (共享權重的小骨幹, MobileNetV3/EfficientNet-B0)
        每個關節輸出: JSN 分量 + erosion 分量 (各自序數/小範圍回歸)
  → 加總所有關節 → 預測 SvH 總分
```

| 階段 | 模型 | 輸入/輸出 | 備註 |
|---|---|---|---|
| 1. 關節定位 | **YOLOv8-pose**（關鍵點）或 YOLOv8n 偵測 | 整手圖 → 每個關節中心點/框 | 關鍵點標註比框/分割省力；文獻 YOLOv7 達 ~99% |
| 2. 逐關節評分 | 共享權重小 CNN | 關節小圖 → (JSN, erosion) 分量 | **所有關節共用同一模型**，等於大幅放大有效樣本數 |
| 3. 加總 | 規則加總 | 各關節分量 → 總分 | 可加一層校正回歸修正系統偏差 |

**為什麼第二層更可能成功（也更有科展亮點）：**
- 逐關節後，每張全身圖變成數十個關節小樣本 → **有效樣本數放大數十倍**，正好緩解小樣本。
- 共享權重 = 一個模型學「一個關節長怎樣」，泛化更好。
- 直接對應臨床 SvH 的逐關節邏輯，Grad-CAM 熱區也更容易落在正確關節 → 可解釋性強。

### 3.3 第三層 未來展望 — 完整管線（不在本屆強求）

```
分割(U-Net, EfficientNet-B0 編碼器) → 關節偵測(YOLO) →
逐關節 JSN/erosion 評分(CNN 或 ViT) → 加總 → (可選)Transformer 做關節間關聯建模
```

> 明確定位為「延伸方向」。送件版本**做到第二層即可達標**；第三層寫進論文的 Future Work，展示視野即可，避免範圍蔓延做不完。

## 4. 遷移學習與抗過擬合 SOP（小樣本核心）

**漸進式微調 3 階段（建議照順序跑）：**

| 階段 | 凍結範圍 | 可訓練部分 | 學習率 | 何時切換 |
|---|---|---|---|---|
| Warm-up | 凍結整個骨幹 | 只訓練新頭 | 1e-3 | 驗證 loss 不再降（約 3–5 epoch） |
| 漸進解凍 | 解凍最後 1–2 個卷積塊 | 最後塊 + 頭 | **分層**：頭 1e-3、解凍塊 1e-4 | 驗證再次穩定 |
| 微調全網(可選) | 全解凍 | 全部 | 骨幹 1e-5、頭 1e-4 | 樣本夠多且未過擬合才做 |

**分層學習率（discriminative LR）示意：**

```python
optimizer = torch.optim.AdamW([
    {"params": backbone_early.parameters(), "lr": 1e-5},
    {"params": backbone_late.parameters(),  "lr": 1e-4},
    {"params": head.parameters(),           "lr": 1e-3},
], weight_decay=1e-4)
scheduler = torch.optim.lr_scheduler.OneCycleLR(optimizer, max_lr=[1e-5,1e-4,1e-3], ...)
```

**小樣本抗過擬合「組合拳」（請全部用上並做消融）：**

- **資料增強**：旋轉(±15°)、水平翻轉(左右手語意可接受)、亮度/對比、CLAHE、小幅平移/縮放。**避免**過度變形破壞骨緣。可選 MixUp/CutMix（對回歸需謹慎）。
- **正則化**：Dropout(0.3–0.5)、weight decay(1e-4)、**early stopping**（看驗證 loss，patience 8–10）。
- **小骨幹 + 凍結**：見上。
- **交叉驗證**：資料少時用 **5-fold（或分組 group K-fold，同病人不跨 fold）**，報告平均±標準差，比單一切分可信。
- **類別不平衡**：分級用**加權交叉熵/序數損失加權**或 **WeightedRandomSampler**；回歸長尾用 log/√ 壓縮 + 對高分樣本過採樣。
- **病人層級切分**：**同一病人的所有影像必須在同一個 fold/集合**，否則資料外洩、準確度虛高（科展評審常問這點）。

## 5. 第二層的標註與小樣本務實落地

關節定位的標註是第二層成本最高處，務實做法：

1. **用關鍵點而非分割**：每個關節點一下中心點（YOLOv8-pose 格式），比畫多邊形分割省 5–10 倍時間。標 16–20 個關節點/手即可。
2. **先標一小批 + 半自動擴充**：手動精標 30–50 張 → 訓練一個粗略偵測器 → 對其餘影像**自動預標**→ 人工只做**修正**（這是省力關鍵）。
3. **用解剖先驗**：手部關節相對位置固定，可用「先偵測手部 bounding box，再用比例網格估各關節位置」當零標註的弱基線，先讓第二層能跑起來。
4. **逐關節標籤哪來**：若資料集只有「整手總分」而無逐關節分數，可採**弱監督/多示例學習**——用整圖總分當監督訊號訓練逐關節模型，或先在有逐關節標註的子集上訓練。**RA2-DREAM 有逐關節標註，若申請到即可直接用。**
5. **量化標註負擔**：誠實在報告寫「標了幾張、花多少時間、標註者是誰、是否有醫學把關」——這本身就是嚴謹度加分。

## 6. Colab 實務（讓它真的跑得完）

| 項目 | 建議 | 說明 |
|---|---|---|
| 混合精度 | **開 AMP**（`torch.cuda.amp` / Keras `mixed_float16`） | 省顯存、加速約 1.5–2×，T4/L4 都支援 |
| Batch size | 16（384px, B0）→ OOM 就降到 8 + **梯度累積** | 梯度累積讓「等效 batch」變大而不爆記憶體 |
| 影像尺寸 | 先 384，穩了再試 512 | 解析度對侵蝕細節重要，但記憶體成本是平方成長 |
| 訓練時間（粗估） | 數百張 × B0 × 384px：**約 30–90 秒/epoch（T4）**，50 epoch 約 0.5–1.5 小時 | **估計值，需自行量測**；YOLO 偵測訓練另計，約數小時 |
| Checkpoint | 每 epoch 存最佳權重到 **Drive**，存 `model+optimizer+epoch+scaler+RNG state` | Colab 會斷線，必須能**從中斷處續訓** |
| 續訓 | 開訓先檢查 Drive 是否有 checkpoint，有就 `load_state_dict` 接續 | 避免每次斷線從頭跑 |
| 防斷線 | 縮小單次 run、勤存檔；資料先打包成少量檔（如 `.npy`/WebDataset）避免 Drive 大量小檔 I/O 慢 | Drive 讀數萬小檔極慢，是常見隱形坑 |

**可重現性（評審必看）：**

```python
import torch, numpy as np, random, os
SEED = 42

torch.backends.cudnn.benchmark = False

# DataLoader 也要設 worker_init_fn 與 generator
```

> 固定 seed、固定資料切分、記錄套件版本(`pip freeze`)、把超參數寫進設定檔並版本控制 → 研究日誌可附這些，重現性是 TISF 嚴謹度的核心。

## 7. 原始計畫建模風險與改善建議

| # | 原計畫做法 | 風險/盲點 | 本規劃的改善 |
|---|---|---|---|
| 1 | 第一層「直接預測總分」 | 全分數範圍回歸**極難**，文獻 ICC 可掉到 0.31，容易得到「看似有相關但實際很差」的結果 | 保底改**序數分級(CORN)**，回歸當進階；回歸用 **Huber + log/√ 壓縮長尾** |
| 2 | 骨幹列 ResNet/EfficientNet/MobileNet 未定大小 | 小樣本配大骨幹 → **過擬合 + Colab OOM** | 明確**首選 EfficientNet-B0 / ResNet-18**，大骨幹須消融證明才用 |
| 3 | 把 SvH 當普通回歸 | 忽略其**序數本質**，相鄰等級錯誤被當成和遠距錯誤一樣 | 引入**序數損失 + Quadratic Weighted Kappa** 評估 |
| 4 | 逐關節評分但未談標註成本 | 逐關節/關節定位標註是**最大隱形成本**，可能做不完 | 用**關鍵點標註 + 半自動預標 + 解剖先驗 + 弱監督**務實落地 |
| 5 | 資料切分只說「同病人不跨集」 | 樣本少時單一切分**方差大、不可信** | 改 **group K-fold 交叉驗證**，報告均值±標準差 |
| 6 | 評估指標未含序數/病人加權 | 與 RA2-DREAM 標竿不可比 | 加 **patient-weighted RMSE、ICC、QWK** |
| 7 | 第二層直接逐關節，未利用「樣本放大」論述 | 沒講清楚為何第二層能緩解小樣本 | 明確點出**共享權重逐關節 = 有效樣本放大數十倍**，是主力賣點 |
| 8 | Colab 訓練未談續訓/可重現細節 | 斷線重跑、結果不可重現 | 補完整 **checkpoint+RNG state 續訓 + 固定 seed** SOP |
