# 05・時程與專案管理藍圖

> 一句話定位：把「16 個月、一個人、免費 Colab」的 RA 手部 X 光 AI 評分科展專題，拆成**每月可交付、可檢核、可降風險**的執行藍圖，讓高中生與指導老師照表操課、把資料申請與課業衝突這兩個最大變數控制住。

---

## 0. 怎麼用這份文件

- **學生**：每月對照「每月里程碑表」確認自己交出了什麼（Deliverable）、達到沒達到「完成定義（DoD）」；每週讀研究日誌制度、每兩週看一次風險登記表的觸發訊號。
- **指導老師／把關者**：看 RACI 分工、檢核點（Gate）與送件檢核清單，知道什麼時候該介入。
- **重要原則**：本文件中所有 TISF 規定為「依官方公告為準」。報名與送件的**精確截止日期，每年由國立臺灣科學教育館（科教館）公告，務必於 2027 年送件年度上官網再次確認**，本文件不臆造日期。

## 4. 研究日誌（Research Log）制度

> 目的：①保護原創性（抄襲比對/問答時自證）②可重現③評審當天**需攜帶**。把它當「實驗室筆記本」與「決策備忘」。

**頻率**
- **每次實驗/每次跑模型**：即時記一筆（最重要，別事後補）。
- **每週**：一則週小結（本週做了什麼、卡在哪、下週做什麼）。
- **每月**：對照里程碑表自評一則。
- **每個重大決策**：單獨記一則（為何選此骨幹、為何改任務、為何啟動 Plan B）。

**記什麼**
- 日期、做了什麼、為什麼、用了哪個資料版本、哪段程式（Git commit hash）、超參數、結果數字、出乎意料的事、下一步。
- 失敗也要記（負結果同樣有科展價值，且能證明過程真實）。

**格式範本（建議 Markdown，存 repo `/log/` 並同步 Drive）**

```markdown
## 2026-08-12  實驗 #017  ResNet18 基線 + 資料增強
- 目標：看資料增強是否提升整圖回歸
- 資料：dataset_v2（後援+正常對照），切分 seed=42，同病人不跨集
- 程式：commit a1b2c3d  notebook: mvp_baseline.ipynb
- 設定：lr=1e-4, batch=16, epochs=30, early stop=5
- 結果：MAE 6.8→6.1，Pearson 0.42→0.51（test）
- 觀察：亮度增強幫助大；旋轉>15° 反而變差
- 異常：第 12 epoch Colab 斷線，從 ckpt 續跑（無資料遺失）
- 決策：保留亮度+小角度旋轉；棄大角度
- 下一步：加 Grad-CAM 看熱區（#018）
- 風險關聯：R6 已備份 ✅
```

**評審攜帶版**：送件前把週小結＋重大決策＋關鍵實驗整理成**精選日誌本（紙本+電子）**，附時間線與 commit 對照，用來回答「這是你自己做的嗎、怎麼做的」。

## 5. TISF 送件檢核清單

> 送件前 4 週開印；**精確截止日以科教館當年公告為準，預留 2 週物流/簽核 buffer**。

- [ ] 確認 2027 送件時學生**年齡未滿 20、在學**（資格證明）
- [ ] 確認**科別**（主：醫學與健康科／備：電腦科學與資訊工程科）

## 6. 版本控制、備援與治理規則

**Git（程式與文件）**
- 一個 repo 管所有 notebook、腳本、報告、日誌（`/src` `/notebooks` `/log` `/report` `/poster`）。
- **每次有結果就 commit**，commit 訊息寫清楚做了什麼；日誌引用 commit hash。
- 重要里程碑打 **tag**（如 `mvp-v1`、`results-frozen`）。
- 大檔（影像/權重）**不進 Git**，放 Drive，repo 內以路徑/說明連結。

**Drive checkpoint（資料與權重）**
- 模型 checkpoint、資料版本（`dataset_v1/v2…`）、結果表都存 Drive 並**版本化命名**。
- **每週固定備份**一次（程式 push、Drive 快照），列為週檢核項（對應 R6）。
- 關鍵節點（MVP 定版、結果凍結、送件版）做**整包快照**另存一份。

**避免檔案遺失**：Colab 斷線→從最近 ckpt 續跑；雙地備援（Drive＋本機/第二雲端）；結果一律帶版本號，禁止覆蓋舊結果。

**避免範圍蔓延（治理規則）**
- 分層鐵則：**MVP 必達 > 進階主力 > 未來展望**；未來展望項一律不進本屆。
- **#11（2027-05）範圍凍結 Gate** 之後，新點子只能寫進「未來展望清單」。
- 每月里程碑只允許「完成既定項」，加項須老師核准且砍掉等量舊項。

## 9. 原始時程的風險點、緩衝與 Plan B

**核心風險：資料申請是關鍵路徑，延遲會骨牌式拖垮後段。**
原計畫「暑假啟動申請」雖對，但若把 MVP 綁在主資料到齊才開始，一旦申請拖到秋冬，進階與寫作全被往後擠，最後在 2027 秋撞上送件死線。

**緩衝與對策**
1. **解耦**：MVP（#2）刻意用**後援公開資料先開跑**，不等主資料；主資料到了再「補做/換資料重跑」，路徑不中斷。
2. **資料 Gate-1（#4，2026-10）**：寄出逾 8 週仍無主資料即做**去留決策**——
   - **Plan A**：主資料已到 → 照表進階。
   - **Plan B**：主資料未到 → 全程以後援資料完成，主線改為「方法嚴謹＋誠實限制」，主資料列為未來工作；仍是有效科展作品（評審重視方法與誠實）。
3. **每階段留緩衝週**：每學期末、每長假末各留 1 週吸收延遲與課業高峰（對應 R7）。
4. **可選項可砍**：練兵賽（#5）、外部驗證（#11/#13）為**可選**，時程吃緊時優先砍，保住 MVP＋進階＋報告＋摘要的主線。
5. **後段保護**：報告與摘要從 **2027-06 起就動筆**（不擠到 9–10 月），9 月只做完稿/海報/演練，10–11 月只做送件，並對截止日預留 2 週 buffer。
6. **送件流程前置**：2027 年初即與老師/學校確認推薦與系統帳號（對應 R9），避免最後一刻卡關。

**一句話 Plan B**：就算主資料始終拿不到、進階只做到一半，只要「MVP 可運作 + 與專家分數顯著相關 + Grad-CAM 合理 + 誠實討論限制 + 完整研究日誌」，仍是一份可送、可答辯、合乎倫理的 TISF 作品。
